# 牛只智能监控平台产品需求文档

文档版本：`V1.0`  
文档日期：`2026-04-06`  
项目名称：`牛只智能监控平台`  
文档类型：`PRD（Product Requirements Document）`

## 1. 项目背景

传统养殖场对牛只状态的监控大多依赖人工巡检，存在巡检频率低、人工成本高、异常发现不及时、历史数据难沉淀等问题。随着计算机视觉技术的发展，基于视频监控的智能养殖管理逐渐具备落地条件。

本项目拟建设一个面向农场主及畜牧业从业者的网页监控平台，结合现有的牛只检测与行为识别能力，实现牛只行为监测、区域语义分析、多摄像头接入、异常预警、历史数据查询与可视化分析，为智慧养殖提供基础平台支撑。

## 2. 产品定位

本产品定位为一个集“实时监控、智能识别、场景分析、异常预警、设备管理、数据追溯”于一体的牛只智能监控平台。

当前项目基础：

- 已具备基于 `YOLOv8` 的牛只识别能力。
- 已具备基于 `KNN` 的牛只基础行为识别能力，可识别 `站立`、`行走`、`卧躺` 等行为。
- 后续重点建设内容为“网页监控平台”及其相关管理、展示、预警与数据能力。

## 3. 目标用户

### 3.1 主要用户

- 农场主
- 养殖场管理人员
- 牧场监控值班人员

### 3.2 用户特征

- 对牛只健康、活动状态、饮水与采食情况有持续关注需求。
- 希望通过监控减少人工巡检压力。
- 希望及时发现异常并保留历史记录。
- 对系统操作复杂度敏感，偏好直观、简单、可视化的页面。

## 4. 产品目标

### 4.1 总体目标

建设一个基于网页的牛只智能监控平台，实现对养殖场内牛只行为的自动识别、区域化分析、异常预警和历史数据管理，提升养殖管理效率，降低人工监控成本。

### 4.2 具体目标

1. 支持通过网页统一接入和管理多个摄像头设备。
2. 对视频画面中的牛只进行实时识别与行为分析。
3. 支持人工标注栏位、水池、采食区等关键区域，提升行为语义判断能力。
4. 提供常见异常行为预设，并支持用户自定义异常行为规则。
5. 当牛只出现异常行为或异常停留时，系统能够生成预警信息。
6. 支持账号密码登录、数据可视化展示以及历史数据查询。
7. 为后续接入无人机、更多智能设备和更复杂算法预留扩展能力。
8. 为后续替换识别模型和部署边缘推理设备预留统一接口。

### 4.3 希望达到的效果

- 农场主能够在一个网页中查看全部监控设备状态。
- 系统能够自动识别牛只基础行为，并结合区域信息判断更具体的场景行为。
- 用户无需持续盯屏，系统可自动提示异常情况。
- 平台能够沉淀历史数据，为后续养殖管理和分析提供依据。
- 系统具备良好的扩展性，后续可平滑增加更多设备类型和算法模块。

- 牛只行为监控总览页面

## 6. 核心使用场景

### 场景一：农场主查看监控总览

农场主登录系统后，可以查看当前所有摄像头在线状态、实时监控画面、异常告警数量、各类行为统计以及近期异常记录。

### 场景二：管理员配置监控区域

管理员进入指定摄像头画面，对水池、栏位、采食区、休息区等区域进行框选标注，系统后续在行为识别时结合区域信息进行更细粒度判断。

### 场景三：异常行为预警

当牛只出现长时间卧躺、异常聚集、长时间停留于某区域或其他预设异常情况时，系统生成告警记录，并在前端页面进行提示。

### 场景四：历史追溯与数据分析

用户可按摄像头、时间范围、行为类型、告警等级等条件查询历史数据，并通过图表查看行为趋势和异常分布。

### 场景五：设备统一管理

用户可在网页端新增、编辑、启停摄像头设备，并为后续无人机等设备接入预留控制入口。

### 场景六：用户配置异常行为规则

管理员可在网页端直接启用系统预设异常行为模板，并根据实际养殖需求调整阈值；同时也可自定义异常行为规则，例如“连续卧躺超过 30 分钟”或“2 小时未进入饮水区”等。

### 场景七：边缘设备上报识别结果

当 `YOLOv8` 或其他模型部署在 `Jetson Nano` 等边缘设备上运行时，边缘端可将识别结果、告警信息、截图地址或视频片段信息通过接口上报到 Web 平台，由平台统一展示、存储和分析。

## 7. 功能架构

本平台整体功能架构如下：

1. 用户与权限模块
2. 监控总览模块
3. AI 行为识别模块
4. 区域标注模块
5. 设备接入与管理模块
6. 告警中心与规则配置模块
7. 历史数据与统计分析模块
8. 模型管理与边缘接入模块
9. 远程控制与扩展接口模块

## 8. 详细功能需求

### 8.1 用户登录与权限模块

### 功能说明

平台支持用户通过账号密码登录系统，登录后进入监控平台首页。

### 功能点

- 用户账号登录
- 登录状态保持
- 退出登录
- 基础权限区分

### 角色建议

- 管理员：可管理设备、区域、用户、告警规则
- 普通用户：可查看监控、查看历史、处理告警

### 验收标准

- 未登录用户无法访问系统核心页面。
- 登录成功后可正常进入首页。
- 退出后系统需清除登录状态。

### 8.2 监控总览模块

### 功能说明

以大屏或控制台形式展示整个平台的运行状态，作为用户进入系统后的核心工作台。

### 页面内容

- 在线设备数量
- 离线设备数量
- 当日识别事件数
- 当前未处理告警数
- 各行为类别占比
- 主要摄像头实时画面卡片
- 最近告警列表
- 最近行为记录列表

### 验收标准

- 用户进入首页后能快速了解全局监控情况。
- 关键指标展示清晰，刷新及时。

### 8.3 AI 行为识别模块

### 功能说明

该模块接入现有算法能力，对监控视频中的牛只进行识别和基础行为判断。

### 当前算法基础

- `YOLOv8`：用于牛只目标识别
- `KNN`：用于基础行为分类

### 模型扩展要求

- 平台默认支持当前 `YOLOv8 + KNN` 组合
- 平台需预留统一模型接入接口，便于后续替换或新增其他检测/分类模型
- 后续可扩展接入 `YOLO` 系列其他版本、`RT-DETR`、自定义行为识别模型等
- 模型切换不应影响前端页面的数据展示结构

### 模型接口设计要求

- 统一输入：视频流、图片、边缘设备上报结果
- 统一输出：目标框、行为类别、置信度、时间戳、来源设备、截图信息
- 统一状态：模型名称、模型版本、运行位置、本地/边缘推理状态
- 支持为不同摄像头绑定不同模型或不同模型配置

### 本模块输出

- 识别时间
- 摄像头编号
- 牛只数量
- 行为类别
- 识别置信度
- 模型名称
- 模型版本
- 推理来源
- 事件截图或关联画面信息

### 支持行为类别

- 站立
- 行走
- 卧躺

### 验收标准

- 系统能够接收算法结果并在前端展示。
- 识别结果能够形成结构化记录，供历史查询和图表统计使用。
- 更换模型实现后，平台接口层无需大改即可继续接入。

### 8.4 区域标注模块

### 功能说明

用户可在摄像头画面上手动绘制关键区域，用于增强行为语义分析能力。

### 支持标注区域

- 水池
- 栏位
- 采食区
- 休息区
- 自定义区域

### 功能点

- 在画面上框选区域
- 编辑区域名称
- 设置区域类型
- 删除区域
- 保存区域配置

### 区域与行为结合逻辑

- 牛只位于水池区域且存在对应动作时，可判定为饮水相关行为
- 牛只位于采食区时，可判定为采食相关行为
- 牛只长时间停留在异常区域时，可触发预警

### 验收标准

- 用户可通过网页完成区域新增、编辑、删除操作。
- 保存后的区域配置能够参与后续行为判断和告警规则。

### 8.5 多摄像头与设备管理模块

### 功能说明

平台支持统一管理多个监控设备，并为后续扩展无人机等设备做预留。

### 支持设备类型

- 固定摄像头
- 可转动摄像头
- 后续扩展：无人机、移动监控设备

### 功能点

- 新增设备
- 编辑设备信息
- 删除设备
- 启用/停用设备
- 查看设备在线状态
- 查看设备最后上报时间

### 设备信息字段建议

- 设备名称
- 设备编号
- 设备类型
- 安装位置
- 视频流地址或本地视频源
- 状态
- 备注

### 验收标准

- 用户能够新增多个设备并统一管理。
- 页面能区分在线、离线、停用等不同状态。

### 8.6 远程控制与边缘推理接入模块

### 功能说明

用户可通过网页对接入设备执行基础控制操作，同时支持接收边缘推理设备上传的识别结果并完成画面集成。

### 本期功能

- 设备启停
- 手动刷新状态
- 发送控制命令接口预留
- 接收边缘设备识别结果上报
- 接收边缘设备截图、视频片段或画面地址
- 将边缘推理结果整合到 Web 监控页面
- 操作日志记录

### 边缘接入要求

- 支持后续将 `YOLOv8` 模型部署到 `Jetson Nano`
- Web 端提供标准结果接收接口，供 `Jetson Nano` 或其他边缘设备调用
- 接口支持上传结构化识别数据、告警数据和画面资源信息
- 平台可根据设备编号将边缘结果映射到对应摄像头画面
- 当边缘设备离线或长时间未上报时，平台应能提示异常状态

### 边缘结果上报字段建议

- 设备编号
- 摄像头编号
- 上报时间
- 模型名称
- 模型版本
- 识别结果列表
- 告警结果列表
- 截图地址或文件标识
- 视频片段地址或文件标识
- 设备运行状态

### 后续扩展

- 云台转向控制
- 焦距调节
- 抓拍
- 无人机起降与巡航控制
- `Jetson Nano` 之外的其他边缘计算设备接入

### 验收标准

- 用户在前端可对设备发起控制动作。
- 系统保留命令记录，便于追溯。
- 边缘设备上报的数据可在对应监控页面正常展示。

### 8.7 告警中心模块

### 功能说明

系统基于识别结果和区域规则，对异常情况进行检测并生成告警。

### 可支持的告警类型

- 长时间卧躺
- 长时间未移动
- 长时间停留于特定区域
- 异常聚集
- 设备离线
- 视频流中断

### 常见预设异常行为

- 持续卧躺超时
- 长时间未饮水
- 长时间未进入采食区
- 在非正常区域持续停留
- 短时间内异常聚集
- 夜间活动异常频繁

### 自定义异常行为要求

- 用户可基于行为类型、区域、持续时间、次数、时间段等维度配置规则
- 用户可为自定义规则设置名称、阈值、告警等级、启用状态
- 用户可编辑、停用和删除自定义规则
- 自定义规则应参与实时告警判断和历史数据查询

### 自定义规则示例

- 连续卧躺超过 `30` 分钟触发高等级告警
- `2` 小时未进入饮水区触发中等级告警
- `10` 分钟内多头牛持续聚集于水池旁触发提示告警
- 夜间 `22:00` 至 `05:00` 行走频率异常升高触发告警

### 告警信息字段建议

- 告警编号
- 告警类型
- 告警等级
- 关联摄像头
- 告警时间
- 告警描述
- 处理状态
- 处理人
- 处理时间

### 验收标准

- 告警记录能在页面中集中展示。
- 用户可查看告警详情并更新处理状态。
- 用户可使用预设规则，并可新增自定义异常行为规则。

### 8.8 历史数据与可视化模块

### 功能说明

用户可以按多维条件查询历史识别数据与告警数据，并通过图形化方式进行查看。

### 查询维度

- 时间范围
- 摄像头
- 行为类型
- 告警类型
- 规则来源
- 模型名称
- 处理状态

### 可视化内容

- 行为趋势图
- 不同行为占比图
- 摄像头事件分布图
- 告警等级统计图
- 每日识别量统计图

### 验收标准

- 用户可按条件筛选历史记录。
- 页面至少支持基础折线图、柱状图或占比图展示。

## 9. 页面需求

### 9.1 登录页

包含账号、密码输入框及登录按钮，页面风格简洁清晰。

### 9.2 首页/监控总览页

作为平台首页，展示核心统计、设备状态、最近告警、最近行为记录和监控卡片。

### 9.3 设备管理页

用于设备的新增、编辑、启停和状态查看。

### 9.4 监控详情页

展示单个摄像头的实时画面、识别结果、区域标注入口、最近行为与告警信息。

### 9.5 区域配置页

在视频画面上绘制并管理区域框。

### 9.6 告警中心页

集中查看所有告警信息，并支持处理状态更新。

### 9.7 告警规则配置页

用于查看系统预设异常行为模板、配置规则阈值，以及新增和管理自定义异常行为规则。

### 9.8 模型与边缘接入配置页

用于配置模型接入方式、模型版本、运行位置以及边缘设备上报参数。

### 9.9 历史分析页

查询历史行为数据和告警数据，并进行图表化展示。

## 11. 非功能需求

### 11.1 易用性

- 页面操作逻辑简单，适合非技术用户使用
- 核心功能三步内可到达

### 11.2 可扩展性

- 支持增加新的行为识别算法
- 支持通过统一接口替换目标检测模型和行为分类模型
- 支持增加新的设备类型
- 支持边缘推理设备接入并统一上报结果
- 支持后续接入无人机控制能力
- 支持面向不同农场客户扩展为多租户部署模式
- 核心能力应采用模块化设计，便于后续拆分为独立服务
- 模型接入、设备接入、规则引擎应尽量配置化，减少硬编码依赖

### 11.3 可靠性

- 摄像头断连时能够提示
- 页面刷新后历史数据不丢失
- 关键业务数据可持久化保存
- 关键服务异常时应具备自动恢复或降级能力
- 识别服务、设备接入服务、Web 服务之间应避免单点故障影响全局使用

### 11.4 安全性

- 登录鉴权
- 基础权限隔离
- 关键操作可记录日志
- 用户密码必须采用安全哈希存储，不得明文保存
- 重要接口应具备身份校验、权限校验和访问频率限制
- 不同农场或租户之间的数据默认隔离，避免越权访问
- 敏感数据和关键配置应支持加密存储
- 系统应保留安全审计日志，便于问题追溯
- 前后端通信和设备上报接口在正式环境中应使用安全传输方式
- 需支持数据备份与恢复，防止因系统异常导致用户数据丢失

### 11.5 性能要求

- 首页在正常网络环境下能够较快加载
- 支持同时管理多个摄像头设备
- 识别结果与页面展示延迟应控制在可接受范围内
- 监控首页应支持分页、懒加载或分批刷新，避免多路画面同时加载造成卡顿
- 历史记录与告警列表应支持分页查询、条件筛选和索引优化
- 高频识别结果应采用异步写入、批量处理或消息缓冲机制，降低主流程阻塞风险
- 视频流展示、识别推理和历史存储应尽量解耦，避免相互拖慢
- 可优先采用边缘推理加平台汇总的方式，降低中心端算力压力和带宽压力
- 需要预留缓存机制，用于首页统计、热点数据和最近告警的快速读取

### 11.6 可运维性与可观测性

- 需记录服务运行日志、接口调用日志、设备上报日志和错误日志
- 需具备基础监控能力，如接口响应时间、设备在线率、告警触发量、边缘上报频率
- 对模型服务、设备接入服务、数据库服务应具备健康检查机制
- 当关键服务异常、设备离线或接口积压时，应能主动提示管理员
- 版本发布应具备配置管理能力，降低后续升级风险

## 14. 风险与注意事项

1. 不同摄像头环境下的清晰度、角度、光照差异可能影响识别效果。
2. 区域标注与行为语义判断规则需要结合实际养殖场场景不断调整。
3. 多设备接入后，系统对数据存储与页面性能会提出更高要求。
4. 若后续接入实时视频流与远程控制功能，需要进一步考虑网络稳定性与设备协议兼容性。
5. 若模型运行在 `Jetson Nano` 等边缘端，需要重点考虑接口稳定性、上报频率、数据格式统一以及断点续传问题。
6. 若项目面向正式发布，需要重点考虑多租户数据隔离、账号安全和生产环境运维能力。
7. 若历史视频、截图和事件数据持续积累，需要提前规划冷热数据分层与存储成本控制。

## 15. 成功标准

若平台达到以下结果，可认为本期产品目标基本实现：

1. 用户可通过账号密码登录系统并进入监控平台。
2. 用户可新增并管理多个摄像头设备。
3. 系统可展示牛只识别与基础行为识别结果。
4. 用户可配置关键区域并参与行为分析。
5. 系统可生成基础异常告警并在页面展示。
6. 用户可使用预设异常行为规则并配置自定义异常规则。
7. 平台可通过统一接口接入新的识别模型或边缘推理设备。
8. 用户可查询历史行为与告警记录，并查看基础可视化结果。
9. 不同用户或不同农场的数据能够做到有效隔离与安全访问。
10. 平台在多设备接入和历史数据增长后仍能保持基本可用的响应性能。

## 16. 总结

本产品需求文档围绕“牛只智能监控平台”进行了整体定义。平台以现有的 `YOLOv8` 牛只识别能力和 `KNN` 行为分类能力为基础，重点建设网页端监控平台，实现设备统一接入、行为结果展示、区域标注增强、告警管理和历史分析等功能。同时，平台补充了异常行为预设与自定义规则、模型可插拔接口以及 `Jetson Nano` 等边缘设备结果接入能力，并进一步从用户数据安全、性能优化、可运维性和未来扩展性角度补充了可发布产品所需的要求，为后续真正落地为 release 级产品打下基础。
